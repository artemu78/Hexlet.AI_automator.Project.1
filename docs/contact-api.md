# Заявки: развёртывание и проверка

SPA на GitHub Pages отправляет JSON в API Gateway → приватную Python 3.12 Cloud Function → YDB Serverless. Письма не отправляются. Публичного метода чтения нет.

## Контракт

`POST /submissions`, `Content-Type: application/json`:

```json
{"id":"a9522dac-166d-4ce7-86ad-1b29265d7d13","message":"Вопрос","contacts":"@telegram","website":""}
```

`id` — UUID, созданный клиентом до запроса. После сетевого сбоя повторяйте **тот же ID и содержимое**. Пробелы по краям удаляются; сообщение содержит 1–1000 Unicode-символов, контакты 1–100. `website` — пустая ловушка. Ответ `200 {"status":"saved","id":"…"}` подтверждает запись или идентичный повтор. Ошибки: 400 — поля/ловушка/нет IP шлюза, 403 — origin, 409 — ID с другим содержимым, 413 — слишком большое тело, 429 — лимит (Retry-After: 600), 503 — временная ошибка. GET не поддерживается. OPTIONS обеспечивает preflight.

Одна SerializableReadWrite-транзакция читает ID и запись лимита, затем записывает обе таблицы. SDK повторяет транзакцию при конфликте. Поэтому параллельные экземпляры не могут принять один ID дважды или обойти лимит. Повтор принятой заявки проверяется до лимита. Лимит скользящий: пять новых заявок за последние 600 секунд; просроченные отметки игнорируются независимо от задержки TTL.

`submissions`: `id` (PK Utf8), `received_at` (Uint64, Unix seconds UTC), `message`, `contacts` (Utf8). **Без TTL**. `rate_limits`: `ip_key` (PK Utf8, HMAC-SHA256 от нормализованного IP), `recent` (Utf8 JSON, до пяти отметок), `updated_at` (Uint64). Только эта таблица имеет TTL 10 минут. Исходный IP не сохраняется. HMAC-секрет генерирует Terraform; его смена сбрасывает лимиты. Не включайте логирование тела запроса в шлюзе. Обработчик не журналирует поля или исключения БД.

## Terraform

Для запуска одной командой заполните `infra/deploy.local.json` по образцу `infra/deploy.example.json`: cloud_id, folder_id и абсолютный путь service_account_key_file. Локальный файл исключён из Git. `npm run deploy -- --plan` проверяет план без создания ресурсов; `npm run deploy` выполняет init, fmt -check, validate и apply с подтверждением плана Terraform. Для автоматического применения: `npm run deploy -- --auto-approve`. Ключ передаётся провайдеру через окружение; YC_TOKEN удаляется из окружения дочернего процесса, чтобы не смешивать способы авторизации. После применения команда выводит URL API. Возможен также ручной запуск:

Нужны Terraform >=1.5, доступ к Yandex Cloud и права для создания ресурсов, таблиц и IAM-привязок. Укажите облако и каталог своего проекта. Учётные данные передаются через стандартный `YC_TOKEN` (краткоживущий IAM-токен) или `YC_SERVICE_ACCOUNT_KEY_FILE`; не сохраняйте их в Git.

```sh
cd infra
terraform init
export TF_VAR_cloud_id=YOUR_CLOUD_ID
export TF_VAR_folder_id=YOUR_FOLDER_ID
terraform plan -out=contact.tfplan
terraform apply contact.tfplan
terraform output -raw contact_api_url
```

Перед apply проверьте план и стоимость облачных ресурсов. Применение выполняется отдельно от изменения кода. По умолчанию CORS разрешает `https://artemu78.github.io` и `http://localhost:5173`; измените `allowed_origins` для другого домена или порта. Origin не содержит путь репозитория. CORS не защищает от спама.

Функция получает `ydb.editor` только на созданную базу (минимальная стандартная IAM-роль YDB для записи; она также разрешает управление схемой этой базы). Отдельный аккаунт шлюза получает только вызов этой функции. Публичной IAM-привязки функции нет: поле `requestContext.identity.sourceIp` доверенное, пользовательский X-Forwarded-For не используется. Посетители не получают credentials YDB.

State, планы и tfvars исключены из Git, но **локальный state содержит HMAC-секрет**. Храните state в защищённом месте с ограниченным доступом, при совместной работе используйте защищённый backend с блокировкой. Не публикуйте state или планы. `infra/function.zip` собирается автоматически из `backend`.

В Settings → Secrets and variables → Actions → Variables задайте `VITE_CONTACT_API_URL` равным Terraform output. Запустите Pages workflow после настройки. Для локальной формы скопируйте `.env.example` в `.env.local`, подставьте URL и перезапустите Vite. URL публичный, секретов в Vite-переменных нет.

## Проверки до развёртывания

```sh
npm ci
npm test
npm run build
python3 -m unittest discover -s backend -v
terraform -chdir=infra fmt -check
terraform -chdir=infra validate
```

Unit-тесты проверяют границы, политику дедупликации/лимита, безопасные ошибки, доверенный IP, CORS и подтверждение клиента. Они не заменяют проверку транзакций в реальной YDB.

## Приёмка после отдельного развёртывания

1. Откройте опубликованный сайт. Отправьте тестовую заявку; дождитесь «Заявка принята». В консоли YDB откройте `submissions`: проверьте ID, UTC-время, обрезанные поля и отсутствие исходного IP.
2. Проверьте пустые/пробельные значения, сообщение 1000/1001 символов и контакты 100/101; повторите через прямой POST, обходя клиент. Заполненная ловушка не должна создавать запись.
3. В DevTools заблокируйте API/отключите сеть: успеха быть не должно, поля сохраняются. При восстановлении сети повторите. Кнопка и поля недоступны во время запроса; закрытие диалога в это время заблокировано.
4. Через HTTP-клиент отправьте несколько параллельных POST с одним UUID. Все успешные ответы должны содержать один ID, в таблице ровно одна запись. Смоделируйте потерю ответа и повторите тот же JSON. Измените сообщение с прежним ID: ожидается 409.
5. С одного IP отправьте пять разных UUID за десять минут; шестой должен получить 429. Параллельно отправьте больше пяти новых UUID, чтобы функция масштабировалась: суммарно принимается максимум пять. Повтор сохранённого ID должен пройти и после достижения лимита. Через 600 секунд новая заявка проходит.
6. Проверьте отказ БД/недостаточные права в тестовом окружении: 503 без содержимого заявки или технических деталей. Проверьте отсутствие чтения через GET, отказ прямого анонимного вызова функции и отсутствие CORS для чужого origin.
7. В консоли схемы убедитесь: TTL есть только у `rate_limits`. После очистки просроченных записей лимита заявки остаются. Удаляйте тестовые заявки вручную.

## Ошибка discovery при первом развёртывании

Если создание таблиц завершилось `failed to initialize table client` → `failed to discover database` → `Unavailable: Service unavailable`, это отказ discovery data-plane YDB, а не ошибка схемы таблицы. Статус базы RUNNING сам по себе не подтверждает доступность discovery. Не удаляйте базу или Terraform state. Повторите `npm run deploy`: уже созданные ресурсы останутся в state, Terraform продолжит создание недостающих. Если отказ повторяется, проверьте доступ к endpoint на порту 2135, доступность YDB и права сервисного аккаунта; не подменяйте эту диагностику бесконечными повторами apply.
