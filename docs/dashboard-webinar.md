# Вебинар: автоматизация создания дашбордов

## Локальный показ

```sh
npm ci
npm run dev
```

Откройте `http://localhost:5173/#/dashboard`. Выберите 7 или 30 дней. Режим «Демонстрационные данные» работает без токенов и облака. Данные вычисляются от текущей даты Москвы; ежедневные продажи воспроизводимы и согласованы с итогами и типами карт. Внизу экрана выберите «Проверка отказа источника» → «Визиты», затем верните «Без отказа». В демо это только локальная имитация.

Путь `#/dashboard` работает на GitHub Pages с любым base path. На лендинге ссылки на него нет. Для подключённых источников задайте публичный **URL API**, не секрет: `VITE_DASHBOARD_API_URL=https://…/dashboard`; после изменения Vite-переменной перезапустите dev-сервер или пересоберите сайт. Ключ доступа пользователь вводит на экране. Он живёт только в памяти вкладки и отправляется в заголовке `Authorization` по HTTPS. Не вводите его на чужом компьютере. Общий ключ не даёт отдельные роли, аудит пользователей или отзыв доступа у одного человека; для постоянного доступа нужна полноценная авторизация. Ссылка и CORS не заменяют эту проверку.

## Путь данных

```text
браузер → HTTP GET → API Gateway → Python Cloud Function → YDB submissions / demo_sales
                                              └────────────→ API Яндекс Метрики
                           ← JSON агрегатов ←────────────────┘
браузер → дашборд
```

HTTP переносит запрос и ответ. JSON задаёт имена и типы полей: `7` — число, `"7"` — строка, `null` означает недоступный показатель, а `0` — достоверный ноль. БД хранит строки заявок и учебных покупок; браузер получает только агрегаты. Облачная функция выполняется без включённого ноутбука. Git хранит версии кода; коммит сам по себе не публикует сайт. GitHub Pages размещает собранный frontend, а API Gateway размещает адрес для серверной функции. Метрика считает визиты сайта; цель `contact_form_submit_click` регистрирует нажатие, а не сохранённую заявку.

## Таблица и API

Terraform добавляет **только** таблицу `demo_sales` в существующую YDB Serverless: `id` (Utf8, PK), `purchased_at` (Uint64, Unix seconds UTC), `membership_type` (Utf8), `amount_kopecks` (Uint64). Все строки этой таблицы — синтетические учебные продажи без персональных данных. Схемы и TTL `submissions` и `rate_limits` не меняются.

Новый `GET /dashboard?days=7|30` доступен только с `Authorization: Bearer <ключ>`. Ответ содержит `period` (включительно от начала первого дня до текущего дня Москвы, сегодняшний день неполный), `generated_at`, `metrics`, `sales_daily`, `sales_by_type`, `sources`. Дневная группировка продаж использует `Europe/Moscow`; UTC остаётся форматом хранения. Заявки считаются по сохранённым строкам `submissions.received_at`, независимо от Telegram. При отказе отдельного источника его значение `null`, статус `unavailable`; данные остальных остаются. Если токена Метрики нет, статус `not_connected`. В ответ не попадают текст заявки, контакты, IP или отдельные заявки. Визиты, заявки и покупки не связаны идентификатором, поэтому конверсия в покупку не рассчитывается.

Метрика вызывается сервером через `GET /stat/v1/data` с `metrics=ym:s:visits`, датами и ID счётчика; ожидание ограничено пятью секундами. Часовой пояс счётчика Метрики должен быть установлен на Москву, чтобы календарные даты совпадали с YDB. [Официальный метод отчёта](https://yandex.ru/dev/metrika/ru/stat/openapi/data_1), [получение OAuth-токена и право `metrika:read`](https://yandex.ru/dev/metrika/ru/intro/quick-start).

## Отдельные шаги развёртывания

1. Скопируйте `infra/deploy.example.json` в `infra/deploy.local.json`, укажите существующие cloud/folder ID и путь к ключу. Файл игнорируется Git. В окружении задайте `TF_VAR_dashboard_access_secret` — длинный случайный ключ. Для Метрики создайте OAuth-приложение только с правом `metrika:read`, получите токен от аккаунта с доступом к счётчику и задайте `TF_VAR_metrica_oauth_token`. При отсутствии токена визиты будут «Источник не подключён». При необходимости переопределите `TF_VAR_metrica_counter_id` (по умолчанию `113655208`). Секреты не помещайте в `VITE_*`, URL или Git. Terraform state содержит секреты: храните его закрыто.
2. Выполните `npm run deploy -- --plan`. Просмотрите план: новая таблица `demo_sales`, отдельная Cloud Function, IAM-привязка вызова, отдельный API Gateway и новое output. Существующая база и таблицы заявок должны остаться на месте.
3. **Отдельно после просмотра** выполните `npm run deploy` и подтвердите план. Возьмите output `dashboard_api_url` для `VITE_DASHBOARD_API_URL`, пересоберите и опубликуйте Pages обычным workflow. Публикация и `terraform apply` не выполняются этим документом автоматически.
4. Только после создания таблицы предварительно просмотрите синтетические продажи: `python3 backend/seed_sales.py --anchor 2026-11-06 --seed 42`. Для актуального показа замените дату на день вебинара по Москве. Команда выдаёт JSON, но не пишет в БД.
5. Для **отдельной записи по решению преподавателя** установите `ydb[yc]==3.29.4`, задайте `YDB_ENDPOINT`, `YDB_DATABASE` из Terraform output или консоли YDB и `YDB_SERVICE_ACCOUNT_KEY_FILE_CREDENTIALS` как путь к закрытому ключу сервисного аккаунта с правом записи в эту БД. Затем выполните `python3 backend/seed_sales.py --anchor 2026-11-06 --seed 42 --write`. Запись использует UPSERT со стабильными ID: повтор с теми же параметрами не создаст дубликатов. Команда ничего не удаляет. Не запускайте её против облака до проверки плана и цели подключения.

## Сценарий на 10–15 минут

1. 0–2 мин: откройте лендинг и прямую ссылку дашборда; покажите отсутствие ссылки в рекламе.
2. 2–5 мин: сравните 7 и 30 дней, карточки и график выручки. Укажите, что покупки учебные.
3. 5–8 мин: покажите JSON `GET /dashboard` и путь запроса через облачную функцию к YDB и Метрике.
4. 8–10 мин: покажите `demo_sales` и preview команды заполнения; объясните UTC, копейки и стабильный ID.
5. 10–12 мин: имитируйте отказ визитов через раскрывающийся блок внизу; сравните `null` и `0`.
6. 12–15 мин: вопросы и ответы. Если подключённый режим настроен, покажите ввод ключа и статусы источников. Без credentials честно оставайтесь в деморежиме.

## Пять вопросов с ответами

1. **После коммита сайт уже опубликован?** Нет. Нужны push и успешный workflow публикации Pages.
2. **Чем `"3900"` отличается от `3900` в JSON?** Первое — строка, второе — число; арифметика требует числа.
3. **Чем ноль продаж отличается от ошибки загрузки?** `0` подтверждён источником, при ошибке значение `null` и статус `unavailable`.
4. **Нажатие «Отправить» означает сохранённую заявку?** Нет. Цель Метрики считает клик; заявка подтверждается записью в YDB.
5. **Продолжит ли работать дашборд после выключения ноутбука?** Опубликованный сайт и облачная функция работают на хостинге и в облаке, а не на ноутбуке преподавателя.
