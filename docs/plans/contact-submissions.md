# Сохранение заявок «Напишите нам» в Yandex Cloud

Статус: согласовано с владельцем проекта.

GitHub issue: https://github.com/artemu78/Hexlet.AI_automator.Project.1/issues/2

## Проблема и результат

Сейчас `src/ContactFormDialog.jsx` проверяет заполнение полей и показывает локальный успех, не отправляя данные. В первой итерации заявка должна сохраняться в YDB; только после подтверждения сохранения форма показывает «Заявка принята».

## Согласованный объём

- SPA остаётся на GitHub Pages.
- Маршрут: SPA → API Gateway → Cloud Function → YDB Serverless.
- Инфраструктура создаётся установленным Terraform: база, таблица, функция, API Gateway, сервисные аккаунты и необходимые права.
- Два обязательных поля: сообщение до 1000 символов и контакты до 100 символов. Удаляем пробелы по краям; пустые значения отклоняем. Контакты — свободный текст (email, телефон или Telegram).
- Повтор той же отправки не создаёт дубль. Идентификатор создаётся до первого запроса и сохраняется для повторов; сервер обеспечивает атомарную дедупликацию. Повтор с тем же идентификатором и другим содержимым отклоняется.
- Пока запрос выполняется, повторное нажатие блокируется. При ошибке или тайм-ауте данные остаются в форме, доступен повтор. Успех возможен только после ответа сервера о сохранении.
- Защита: скрытое поле-ловушка и серверное ограничение частоты запросов; CAPTCHA в первую итерацию не входит.
- Просмотр заявок — через консоль Yandex Cloud. Админка не входит в объём.
- Почтовые уведомления — вторая итерация. Тогда сбой почты не отменяет принятую заявку, отправка повторяется автоматически.

## Хранение и защита

- Ограничение: не более 5 новых заявок за 10 минут с одного IP; проверка выполняется на сервере и работает между экземплярами функции. Повторы уже сохранённой заявки не расходуют лимит новых заявок. Источник IP берётся из доверенного контекста шлюза, не из произвольного заголовка клиента.
- При превышении лимита — понятное сообщение и возможность повторить позже. Поле-ловушка не должно создавать запись в базе.
- Храним ID заявки, время приёма в UTC, сообщение и контакты. Для ограничения частоты — отдельные краткоживущие записи с необратимым ключом на основе IP; исходный IP в заявку не записываем.
- Заявки хранятся бессрочно, без TTL и автоматического удаления. При необходимости владелец удаляет их вручную через консоль. Краткоживущие записи ограничения частоты хранятся отдельно от заявок.

## План реализации

1. Описать API и таблицы; определить атомарную дедупликацию и распределённый лимит запросов.
2. Добавить Terraform-конфигурацию, переменные и инструкцию развёртывания. Не включать секреты и state в Git. Доступ функции к базе — через сервисный аккаунт с минимальными необходимыми правами; прямой публичный доступ к данным не предоставлять.
3. Реализовать обработчик: проверка входных данных, ловушка, дедупликация, лимит, сохранение и безопасные ответы об ошибках. Не писать сообщения и контакты в логи.
4. Подключить форму к API через публичный URL в конфигурации сборки; настроить CORS для адреса сайта и локальной разработки. CORS не считать защитой от спама.
5. Обновить README и GitHub Pages workflow для передачи URL API при сборке. Существующая цель Метрики остаётся целью клика; данные заявки в аналитику не передаются.
6. Проверить сценарии ниже и описать ручную проверку записи в консоли.

## Критерии приёмки

- Корректная отправка создаёт запись в YDB и показывает «Заявка принята».
- Пустые поля и превышение лимитов отклоняются и клиентом, и сервером. Границы: 1000/1001 для сообщения, 100/101 для контактов.
- Ошибка базы, сервера или сети не показывает успех; введённые данные доступны для повтора.
- Повтор после потери ответа и параллельные запросы с одним ID создают ровно одну заявку. Изменённое содержимое с прежним ID отклоняется.
- Ловушка не создаёт запись; серверный лимит работает при нескольких экземплярах функции.
- Посторонние посетители не могут читать заявки через публичный API.
- `npm run build`, проверки обработчика, `terraform fmt -check` и `terraform validate` проходят. После отдельного развёртывания выполнена проверка формы с опубликованного сайта и записи в YDB.
- В первой итерации письма не отправляются.
- У заявок нет срока автоматического удаления; очистка записей ограничения частоты не затрагивает заявки.
